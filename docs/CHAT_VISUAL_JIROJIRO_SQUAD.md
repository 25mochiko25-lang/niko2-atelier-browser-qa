# NIKO² ATELIER / CHAT ONLY・ジロジロ視覚監査チーム
更新：2026-10-17。Founderから別途最新指示があればそれを優先する。

## 目的・絶対境界
NIKO² ATELIERの **Production `https://niko2atelier.com/` の実画面** を、Founder参照端末 iPhone 15 Plus相当の 430×932 / mobile / touch / WebKit で観察する。**ビジュアルと画面上の操作感だけ** の監査。改善実装、CSS書換え、Production/Combined配信、D1変更、プラグイン設定更新、サービス課金作業は実行しない。
**Codex、Work、NIKO2-AUTO、サブエージェントを一切使わない。** 既存のGitHubプラグインを使うChatが自分自身で結果確認・操作・報告まで行う。追加の新規ワークフロー・新規環境を作らない。
既存の `LIVE_OBSERVER.md` と `docs/CHAT_READONLY_FOUNDER_QA.md` の操作手順を使う。必要なファイルのみ読む。

## 視覚判定の基準
- 430×932は **Founderが美術上の基準にしている端末** 。このサイズで「他端末の救済用」磨りガラス帯・意味のない余白・二重スクロール・見切れ・謎の縮尺変化が出たら疑いとして必ず挙げる。ただし画像をやみくもに cover 拡大して主役を切らない。
- 意味のある長文のスクロールは許可する。意味のない空白への縦移動、バウンドに見える不要な動き、開閉に伴う位置飛びは不合格候補。モバイルWebKitでの擬似ホイール操作はiPhone指スワイプの再現ではないため、指スワイプ/bounce実証とは言わない。
- 画質・画像読み込みは、文字・素材の明瞭さ・荒れ・ロード前後での大きなレイアウト移動として見たままを記録する。スクリーンショットしかないのにFPS・音質・動画の滑らかさ等はPASSとしない。
- 同一施設の同格の画面や部品を比較し、**ここだけ急に小さい/大きい/左右の比率や間隔が異なる** ものを探す。施設ごとの固有ルールを平坦な共通UIに強制しない。
- タップ連打を強制せず、必要な余韻・適度な連打ガードは残す。反応が遅い/長すぎる演出で詰まる/操作が戻るとズレるなら記録。理由なく待たされることを「上品な演出」として免責しない。
- **見た目の合否は実際のスクリーンショットを見て判断。** DOMに収まった・ボタンを押せた・自動QA PASSだけではビジュアルPASSを付けない。画像を表示できない場合「見られない」と明記。
- 最初は視覚ブラインド評価。過去の修正報告、CSSのコメント、Founderの意図、他隊員の結果を読むのは **初見の観察記録を固定した後** 。原因や過去の合格理由を調べる段階は任意で、実測と推測を分ける。既知バグを押し付けたり不必要に同調しない。
- 画面に出ている仕様のない施設や製作中部分を勝手に現行Productionの不具合と呼ばない。到達できなければ未到達と記す。

## チーム・持ち場
**A 入口の異物探知**: HOME → 初回Intro → Garden入口 → 探索開始。横/縦余白、救済帯、写真の縮尺、操作エリア、初見の違和感を独立に観察。見た目が違うと思ったら隣接場面を比較。
**B Garden・お土産の番人**: 5つの発見、各記憶ウィンドウ、戻る/再表示、門、Ending、「持ち帰る」、WORLD MEMORYの1枚/2枚、言葉を添える表示・閉じるまで。Garden内の構図・カード寸法・余白統一。
**C WORLD・Research Labの観察員**: HOMEからWORLD、Research Lab入口・観測台・記録表示・奥の保管室・運用クリップボード等の到達可能部分。各施設内のサイズ統一と戻る導線。届かない経路は無理やり開かず報告。
**D ROOM NULLの扉番**: WORLDからROOM NULLの扉、扉を開く、室内、Cabinet/CHANNEL 00/Diaryに接続する見える操作。もしProductionから曜日部屋に辿れるなら部屋ごとの構図、カーテン/照明。Previewだけの部屋は確認済みにしない。
**E 文字と窓の検品**: Diary、FROM THE ATELIER、記事、手紙ポップアップ、表示できるモーダル・通知・写真選択。文章の善悪でなく読めるサイズ、窓幅、長文の必要スクロール、ボタンの可視/重なり/入力時の大きな画面ズレを監査。個人情報や自由文を投稿しない。
**F 異種施設と横断比較**: Hotel、Perfume、CHANNEL 00、その他公にたどれる未観察施設へ進み、近い状態で急に縮尺・操作ルール・画質が変わる箇所を探索。たどり着けなければ未到達。無理に隠しUIを解析しない。

## 既存のChat専用安全なWebKitルート
ChatからGitHub接続を使い、独立した新規 `live-requests/<session>.json` を**1セッションにつき1コミット**で作成。次の形式を厳守。
```json
{
  "session": "mofu-vis-b-20261017-unique",
  "target": "https://niko2atelier.com/?mofumofu_qa=mofu-vis-b-20261017-unique",
  "mode": "observer-driven",
  "device": "founder",
  "readOnly": true
}
```
`session` の実値は各隊員が固有な小文字/数字/ハイフンから成る文字列で生成し、衝突・再利用しない。 `device: founder` は430×932。 `readOnly: true` で初回navigation前にservice workerをブロックし、GET/HEAD以外の通信をブラウザ側で遮断。これで一般Visitor登録や観測送信のPOSTを防ぐ。あくまで **読み取り専用・正式Identity未署名** の独立監査IDであり、`mofumofu_qa` URLパラメータをD1署名の名札扱いしない。
レポート/スクショは **公開リポジトリに残る** 。ログイン不要の公開内容だけ扱う。メール、自由文、個人的な日記、秘密、実在顧客情報を扱わない。送信・保存を必要とする操作の完了を推定しない。

運用は `live-results/<session>/state.json` の `lastCommand`, `controls`, `screenshotUrl` を読み、本当に見えている画面を画像で確認し `live-control/<session>.json` に1操作ずつ書く。 `lastCommand` が今回のIDへ変化してから次へ進む。スクショのURLは常にその時点のcommitで固定されたものを記録する。WebKitの画像は既存runがGitHubに保存したものを優先し、余計なCloudflare Browser Renderingなど従量課金ツールを起動しない。料金不明の有料外部APIを使わない。
GitHubプラグイン権限不足などで画像が見られない場合は監査不能と報告し、Codex / Workに切り替えない。

**セッションは20分操作がないとinfra idle stop、最大90分runnerガード**。Chatが途中で切れたら、新Chatへsession名とrepoを渡し、まだrunnerがliveなら現在state/lastCommandから安全に再開。終了済みなら新しいユニークsessionを起こす。既存の他隊員の `live-control` を触らない。終了時は必ず `op:"stop"` を書き、`state.stopReason` を確認する。説明が長いだけのポーリングや重複訪問はしない。

## 報告
実画面の所見だけを出す。次の4分類で短く、場所を絞って記録：
**確定した画面上の不具合 / 目立つ違和感 / 比較対象が足りないもの / 未到達**。
各所見には「現場・到達ルート」「何を押したか」「何が見えたか」「なぜ異常に見えるか（比較対象）」「画像（commit固定のURL）」を入れる。優先度はP1=Founder端末の目立つ崩れ、P2=局所的なバランス/見切れ、P3=小さな違和感とする。 **実装提案やCSS原因の調査は原則、初回観測レポートを固定した後だけ**。
本番の製品ファイル、Production、Identity、D1、GitHubの他隊員ログは変更しない。最終レポートはQA repoの `docs/qa-reports/visual-<session>.md` に保存してリンクを返す。別隊員の報告とマージ・上書きしない。
